NeuroVisor BCI Audit

A full read of the June 2025 master's project, covering the extraction scripts, the seven model notebooks, and all 38 EDF recordings. It reports what each file contains, which scenario it follows, what the code does well, where it breaks, and what we measured when the data was evaluated without leakage.

38 EDF files · 4.3 h of EEG30 ch · 500 Hz · µV3 classes: neutral / push / walk10 participants (S01–S10)

Verdict

The recordings are usable. But no model trained on them so far has been shown to decode push or walk. The accuracies reported in graphs.py (35–50% on three classes) sit just above the 33% chance level. They also come from pipelines with feature and scaling bugs, so the number cannot be read as model quality at all. When we re-ran a correct Riemannian baseline, the result depended almost entirely on how the windows were split:

98%
median balanced accuracy, random 5-fold split of windows (what the notebooks did)
36%
same model, but train and test windows come from different blocks
100%
accuracy at telling push block 1 from push block 2, which are the same class
35%
leave-one-subject-out balanced accuracy, chance = 33%

Two windows from the same block are nearly identical. Two blocks of the same command are perfectly separable. So the EEG mostly encodes when a window was recorded (drift in electrode impedance, fatigue, eye state, alertness), not what the person was imagining. The design is a fixed timetable of long blocks with no randomisation and no cue-locked trials, and that makes class and time inseparable. The first improvement needed is therefore in evaluation and in the recording protocol. A bigger network comes later.

Dataset & device

Read from the EDF headers, not from the folder names.

Acquisition

  • Device / exporter: Neurosoft NeuroVisor (SNEdfConverterNeuroVisor)
  • Montage: 30 EEG channels, 10-10 positions, all referenced to TP (labels like C3-TP). Motor strip covered by C3, Cz, C4, FC1/2, FC5/6, CP1/2, CP5/6.
  • Sampling: 500 Hz, physical unit µV, rank 30, so no reference channel is stored.
  • Hardware prefilter, already applied: HP 0.5 Hz, LP 70 Hz, Notch 50 Hz. The measured spectrum confirms a −15 dB notch at 50 Hz and steep roll-off above 80 Hz.

Markers inside each file

  • Every protocol file carries timed annotations named EC / EO at exact whole seconds. These are the block boundaries.
  • Scenario 1 has a boundary at 120 s marked EC→EO. The code ignores it and labels 0–240 s as one neutral block, which merges an eyes-closed baseline into "neutral".
  • Scenario 2 starts with EC at 0 s, which is the push#1 block. Section 6 tests whether that block was really eyes-closed.
  • One file has a PAUSE marker at 148.6 s. Two crops end with BAD_ACQ_SKIP.

The two protocols

Scenario 1: 480 s, block order neutral → push → walk
11 recordings used (S03, S05, S06, S08, S09 ×2, S10 ×1), plus one 440 s recording (S07) never used. Neutral is 75% of the time.
Neutral, eyes closedNeutral / restPushWalkdashed = EDF marker
Scenario 2: 500 s, push and walk alternate in long blocks
15 recordings used (S01 ×3, S02 ×3, S04 ×4, S05 ×2, S07 ×3), plus S02·1 never used. Neutral is only 8% of the time.

Because the class balance differs so much between scenarios (neutral is 75% of scenario 1 and 8% of scenario 2), a model trained on both pooled can partly learn "which scenario / which person" instead of "which command". Within each scenario the commands always come in the same order. Push is always first, so "early in the session" and "push" are the same thing to a classifier.

Signal quality

The raw signal is clean by EEG standards. Median channel σ is 5–10 µV after a 1–45 Hz band-pass, no channel is flat, and the hardware notch leaves no 50 Hz residue. The main contaminant is ocular. In several files Fp1/Fp2 carry 1.5–5× the peak-to-peak amplitude of the occipital channels, and some recordings (S09·2, S07·4, S05·5) have 20–30% of seconds exceeding 150 µV peak-to-peak. Blinks and eye movements are time-locked to the instructions ("push", "walk"), so a classifier can learn eye behaviour instead of motor imagery. Frontal channels need to be cleaned (ICA / regression) or at least monitored as a confound.

The core problem: time is a stronger signal than the command

Model: covariance (OAS) → Riemannian tangent space → logistic regression, on 2 s windows, 8–30 Hz, 0.5 s step. 1 s is dropped at each block edge. Metric: balanced accuracy, so the 75% neutral share in scenario 1 cannot inflate it.

What this means for the PFE numbers. Any accuracy computed with train_test_split on windows of these recordings measures temporal leakage. What the signal contains

Log-power differences in dB, median over recordings. Task blocks are compared against the eyes-open rest blocks of the same recording.

Which EC markers mean eyes closed

  • Scenario 1, yes. Occipital alpha in 0–120 s is +8.0 dB above 120–240 s (higher in 11/12 recordings). The first 2 minutes of "neutral" are a resting eyes-closed baseline, a different brain state from the rest of the class. Give it its own label or drop it.
  • Scenario 2, no. Push#1 (the EC-marked block) vs push#2/#3 is -0.6 dB (higher in only 2/16). There, EC is just the software's first marker. The push#1 block is usable.

Task vs rest contrasts (scenario 2)

  • Central (C3/Cz/C4) mu 8–13 Hz: push +0.3 dB, walk +0.3 dB
  • Central beta 13–30 Hz: push +0.3 dB, walk +0.4 dB
  • Occipital alpha: push +0.1 dB, walk +0.4 dB
  • Fp1/Fp2 beta (muscle/eye): push +0.2 dB, walk +0.3 dB
  • Push − walk directly: central mu -0.1 dB, central beta -0.1 dB

Scenario 1 contrasts: central mu push -0.1 dB / walk +1.3 dB; occipital alpha push +0.5 dB / walk +1.5 dB; push − walk central mu -0.5 dB, occipital alpha -0.8 dB.

No motor-imagery signature at the group level. Motor imagery should produce a central, lateralised decrease of mu/beta power (ERD) during the task. Here the task blocks show the opposite sign or nothing: scenario 2 task vs rest is +0.3 to +0.4 dB at every site, and the walk blocks of scenario 1 (late in the session) carry the largest alpha increase, both centrally and occipitally. That pattern fits alpha rising slowly with time on task (relaxation, drowsiness). It is the drift found in section 5, and the push − walk difference is larger over the occipital cortex than over the motor strip. "Push" and "walk" are also not body-part-specific imagery tasks (like right hand vs feet), so there is little neurophysiological reason to expect distinct spatial patterns.

Code review

Ordered by impact on the results. Notebook references use cell numbers.

Critical

Features are computed across channels, not across time

read_eeg returns windows shaped (samples, channels), but extract_features takes every statistic with axis=1, which is the channel axis. Each "feature" is the median/std of the 30 channels at one time sample, giving 1000 features per 1 s window. That is a spatial snapshot, not a per-channel descriptor. The nperseg=128 > 30 warnings in the LR notebook come from this: Welch was run over 30 channels. The band powers are computed and then thrown away (line 180 keeps only median and std).

utils.py:155–184 · used by LR, KNN --features, Random Forest
Critical

Training data is only scaled on the last channel

In read_eeg(why="train") the line X[:, i] = scaler.transform(...) sits outside the for loop, so only channel 29 (Fp2) is standardised. The test path scales all 30 channels with the same scalers. Train and test therefore live in different units for 29 of 30 channels.

utils.py:104–109
Critical

EEGNet input is scrambled by reshape

X_train.reshape(N, 30, 250, 1) on an array shaped (N, 250, 30) reorders memory instead of swapping axes. The "channel" rows the network sees are interleaved chunks of time and electrodes, so its spatial depthwise convolution has nothing to learn. It needs np.transpose(X, (0, 2, 1)).

EEGNet/newEEGNET.ipynb cell 7
Critical

EEGNet was trained on one test file, and a plotted curve is synthetic

Cell 3 loads read_eeg(why="test"), which gives 120 windows from a single person, and then randomly splits overlapping windows. best_model stores a reference to the live model (not a copy) and records the training accuracy (88.9%). Cell 13 builds an "accuracy from 33 to 87%" curve from random.random(). That cell must not be used for any figure. Only the real losses_t / accuracies lists from cell 12 are measurements.

EEGNet/newEEGNET.ipynb cells 3, 12, 13
Critical

CSP / ICA / PCA are fitted separately on train and on every test file

apply_fbcsp, applyICA and applyPCA call fit_transform each time. In the SVM notebook the test features come from projections fitted on the test file itself, using its labels, and the train features come from a different projection. The two feature spaces don't correspond, which is why every SVM configuration scores 34–36% and MRFO never moves past 0.3568.

utils.py:195–272 · SVM/SVM mrfo.ipynb cells 5–6
High

Hyper-parameters are selected on the test set

SVM-MRFO's fitness function scores on X_test. The RF notebook's Optuna objective returns test accuracy. LR loops over 26 test files and keeps the best one. All three report the maximum over many test-set evaluations, which is an optimistic number. Use a validation split (blocks or sessions) for selection and touch test once.

SVM cell 11 · random forest/bop_sdxl_lora_train_512_384.ipynb cell 3 · LR cell 10
High

Random window splits leak

KNN (train_test_split, stratified), fuzzy (30% stratified) and EEGNet all split overlapping windows from the same recordings at random. The measurements above show this alone lifts a model that sits at 36% on held-out blocks to 98%.

What is good and worth keeping

Keep

A real dataset with sessions

10 participants, 28 unique scenario recordings (+1 on a third protocol), 1–6 sessions for most people, 30 channels with full motor-strip coverage, consistent 500 Hz EDF with embedded markers. That is enough to study cross-session transfer, which most student BCI projects can't.

Keep

Two protocols with different orderings

Scenario 2 alternates push/walk three times. It is the closest thing to a control for time and is what made the block-split evaluation possible.

Keep

The right model families were tried

CSP/FBCSP, EEGNet with depthwise spatial filters, class balancing, per-channel scalers persisted to disk for online use, early stopping, and Optuna and metaheuristic search. The ideas are sound. The bugs above are in how they were wired together.

Keep

Held-out test per recording

The committed data_processing.py exported the last 20% of every block per file. That is a temporal hold-out, and it was the right instinct.

Engineering plan: the best model this data can support

Ordered by expected gain. Steps 1–2 have to come first because they decide whether later gains are real.

1 · Evaluation that cannot lie

  • Split by block (within session), session (within person) and person (LOSO). Never split by window. Report balanced accuracy, Cohen's κ, the per-class confusion matrix and ITR (bits/min) for the online case.
  • Always include a time-only baseline (predict from window timestamp) and the drift test above. A model has to beat both.
  • Lock the test sessions before any tuning. Nested CV for hyper-parameters.

2 · Data and protocol (largest lever)

  • Cue-based, randomised trials: fixation 2 s → cue (push / walk / rest) → 4 s imagery → 2–3 s jittered rest. Use 40+ trials per class per session in randomised order, so class is no longer confounded with time.
  • Body-part-specific imagery for distinct spatial patterns: e.g. "push" = both hands pushing / right hand, "walk" = feet, plus rest. Hand vs feet has a known topography (lateral C3/C4 vs Cz).
  • Event markers from the stimulus program (LSL or the NeuroVisor trigger input), not typed at whole seconds afterwards.
  • Record a 1-minute eyes-open + 1-minute eyes-closed baseline as their own labels, plus a short EOG calibration (blinks, saccades) for artifact regression.
  • Keep the existing 31 recordings for pre-training and drift studies, and include S02·1 and S07·2.

3 · Preprocessing

LoadEDF from all_data only, deduplicated by hash, markers → events
Filterkeep HW 0.5–70 Hz + notch, then 1–40 Hz zero-phase offline / causal SOS online
Bad channelsrobust z of variance, correlation, HF noise → interpolate
Re-referencecommon average, or a small Laplacian around C3/Cz/C4
ArtifactsICA + ICLabel offline, ASR or EOG regression online. Reject epochs >150 µV p-p
Alignper-session Riemannian re-centring / Euclidean alignment

The re-centring step targets exactly the drift measured in section 5. Each session's covariances are whitened by that session's own mean (estimated from rest data). This is the single most effective cross-session fix in the literature for this kind of shift.

4 · Features

  • Filter-bank covariance → Riemannian tangent space (4–8, 8–12, 12–16, 16–24, 24–30 Hz), concatenated, with shrinkage covariance. This is the strongest classical MI feature.
  • FBCSP log-variance fitted on training folds only, with mutual-information band selection.
  • ERD/ERS relative to each trial's own pre-cue baseline (dB), which cancels slow drift by construction.
  • Control features to monitor, not to classify on: Fp1/Fp2 power, occipital alpha, EMG band (>30 Hz) on temporal channels.

5 · Models, from baseline to state of the art

Classical (start here)

  • MDM / TS + LR (pyRiemann). Strong, fast, a few ms per prediction.
  • FBCSP + shrinkage LDA, the reference MI pipeline.
  • Per-user calibration of 5–10 min with Riemannian transfer from the other 9 participants.

Deep (once data is cue-based)

  • EEGNet / ShallowConvNet / ATCNet / EEG-Conformer via braindecode, with input shaped (batch, 1, 30, T) and per-session alignment.
  • Augmentation: time shift, channel dropout, Gaussian noise, mixup within class.
  • Pre-train on all participants, then fine-tune the last layers per user. Optionally start from a public EEG foundation model (e.g. LaBraM-style encoders) and evaluate it under the same splits.
  • The RTX 3060 (6 GB) on this machine is enough for all of these.

Hyper-parameters: tune window length (1–4 s), band set, shrinkage and C with Optuna using nested session-wise CV. Expect a well-designed 3-class hand/feet/rest protocol to reach about 60–80% online for good performers. A sizeable minority of users ("BCI-inefficient") stay near chance whatever the model.

Real-time design

StreamNeuroVisor → LSL (pylsl is installed) or vendor SDK, 500 Hz chunks
Ring bufferlast 2–3 s × 30 ch, causal SOS filters with carried state
Every 100–250 mscovariance → re-centre → TS → classifier, <10 ms
SmoothEMA of probabilities over ~1 s, softmax temperature from calibration
Decidefire only if p > threshold for N consecutive updates (dwell), else "idle"
Adaptupdate the session mean from idle periods (unsupervised re-centring)
  • Use the same code path offline and online: one Pipeline object pickled with its scalers and filters, and replay recorded EDFs through the online loop to measure latency and false-activation rate before going live.
  • Treat "neutral / idle" as the default state, with an explicit reject option, so the device does nothing when unsure. Measure false positives per minute during rest, which matters more for device control than accuracy.
  • Target end-to-end latency (window centre → command) under 1 s, and log every prediction with timestamps for later analysis.
